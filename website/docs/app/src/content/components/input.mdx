## Install

```sh
npx tracky add input
```

`Input` requires the `utils` item for `cn()` and lists no analytics dependency. The package is not published yet, so install `utils` alongside it once a release exists.

`Input` has no `analyticsName`, because it sends no component event. Page-wide input capture, when you enable it, reads the same `data-analytics-name` attribute on any element.

## Action

`Input` sends no component event and does not render `data-tracky-component`. It has no analytics code at all, so nothing about the field, its value, or its focus can reach the SDK from this component.

If `capture.inputChanges` is on, the SDK's own page-wide listener records `input_interaction` for a `change` with element metadata only. That listener skips password inputs and hidden inputs, and it never reads the value.

## Keyboard and screen readers

- Typing, selection, and clipboard behavior are the browser's.
- Tab reaches the field unless it is disabled.
- Focus shows a `focus-visible` ring; the field keeps its native semantics.
- Disabled uses the native attribute and a muted surface.
- `aria-invalid="true"` switches the border and ring to `destructive`; connect error text yourself with `aria-describedby`.
