## What Tracky does

Tracky is a React analytics SDK. You call `analytics.track()` for the product events you want to measure, and the SDK buffers them in the browser and posts a JSON batch to the endpoint you configure. Your endpoint owns validation, storage, retention, dashboards, and access.

Tracky is not a hosted analytics service. It does not run a collector, a database, or a dashboard for you, and it never sends to an endpoint you did not configure.

The component library is separate: `tracky add` copies React primitive source into your app. The primitives are not exported by the SDK package. Neither the SDK nor the component library is published yet, so the install commands in these pages describe the release steps rather than a package you can install today.

## The event path

<Steps>

1. Your app calls `analytics.track()`, `analytics.trackComponentEvent()`, or a Tracky primitive emits its documented action.
2. The SDK adds an ISO timestamp, the current route, your context, and a random tab-scoped session ID.
3. The SDK holds the event in a bounded buffer and posts batches to the endpoint you set on `AnalyticsProvider`.
4. Your endpoint validates, stores, and queries the events.

</Steps>

Page-wide capture is a separate, opt-in layer. Mounting the provider or using a primitive turns on no clicks, forms, input changes, frustration clicks, heat maps, scroll depth, or engagement time.

## What the docs site does not do

The docs shell mounts no provider and sends nothing. Only a live example mounts one, against a reserved `.invalid` endpoint that the page answers itself, so interacting with an example never reaches your endpoint or any Tracky service.

## Where to start

If you are wiring an endpoint and a first event, start with [Getting started](/sdk/getting-started). If you are deciding what to collect, read [Capture switches](/sdk/capture-switches) first, then check the privacy boundaries beside it.
