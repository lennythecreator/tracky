# Tracky landing page

- **Mode:** Persuade. Help React developers understand the planned component library, the current SDK scaffold, and how the event path works.
- **Audience:** React developers and small teams with an endpoint they already operate.
- **Promise:** Tracky is planned as a reusable React component library paired with an analytics SDK. Browser events go to the endpoint the developer configures; Tracky does not host a collector or dashboard.
- **Primary action:** Explore the analytics SDK setup (`#quick-start`).
- **Chosen direction:** Workflow-style event diagram. A planned Tracky UI component, the analytics SDK, and the configured endpoint connect in a previewable component → Tracky → endpoint route; explanation, a planned-library preview, and setup code orbit that diagram.
- **Pinned choices:** Soft blue and white, Plus Jakarta Sans, diagram-led composition with node ports, labeled connections, and a restrained event preview.
- **Visitor path:** Clear product and development status → illustrated app-to-endpoint event flow → planned component preview → current SDK capabilities → sample event → SDK setup snippet.
- **Honesty constraints:** Label the route animation and component preview as illustrative. State that Tracky is in early development and the component library is not shipped; do not claim npm release, hosted endpoint, or guaranteed delivery.
- **Privacy constraints:** Automatic capture is opt-in and never reads field values. Do not imply Tracky provides consent management or legal compliance.
- **Copy rules:** Lead with the SDK's current job and developer-owned endpoint. Label the component library as planned wherever it appears. Name the actor for each step (app, SDK, endpoint), use concrete verbs, and keep technical examples aligned with the source.
- **Writing reference:** See [developer-copywriting.md](research/developer-copywriting.md) for source-linked guidance and the landing-page checklist.
